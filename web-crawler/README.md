# 개인정보 응답 검토기 2.0.0

Burp Suite Pro의 HTTP history XML을 로컬에서 검사하고 검토 판정을 저장하는 도구입니다. 개인정보 포함 가능 응답을 찾는 보조 도구이며, 개인정보 부재·접근권한·취약점 여부를 자동 확정하지 않습니다. 크롤러는 선택 기능입니다.

## 바로 사용하기 — Burp XML 검사

1. ZIP을 모두 풉니다.
2. `pii_finder.html`을 최신 Chrome 또는 Edge로 엽니다. **Python 설치나 서버 실행이 필요 없습니다.** 기관 브라우저 정책이 로컬 HTML 열기를 차단하면 아래의 로컬 웹 화면 방식을 사용하세요.
3. Burp Proxy HTTP history에서 검사할 항목을 선택해 **Save selected items**로 XML을 저장합니다. 응답을 포함하고 Base64 저장을 권장합니다. Burp 프로젝트 파일 자체가 아니라 내보낸 XML이 필요합니다.
4. XML을 파일 선택 또는 끌어 놓기로 불러옵니다. 제공된 `sample_burp.xml`로 먼저 동작을 확인할 수 있습니다.
5. ‘분석 범위와 미완료 응답’을 펼쳐 입력·완료·일부 검사·실패·미지원·제외·응답 없음 수를 확인합니다. 파일 자체가 실패하면 해당 파일의 거래 수는 미검증으로 표시합니다.
6. 응답 코드 필터로 2xx 또는 기타/미상을 나눠 볼 수 있습니다. 필터는 표시만 바꾸며 원거래를 삭제하지 않습니다. HTTP 200만으로 업무 성공·정상 권한 응답이라고 판단하면 안 됩니다.
7. 결과 원문과 업무 권한을 확인한 뒤 정탐·오탐을 직접 선택합니다. 최초 판정은 모두 ‘확인 필요’입니다. 동일 값 묶음의 판정은 해당 묶음의 발생 전체에 적용되므로, 문맥이 다르면 ‘중복 묶기’를 끄세요.
8. ‘프로젝트 저장’은 원문·요청·설정·판정을 함께 저장합니다. ‘프로젝트 불러오기’로 이어서 검토합니다. ‘마스킹 보고서 저장’은 전체 탐지와 분석 범위를 JSON으로 저장하며 화면 필터로 숨긴 결과도 포함합니다.

프로젝트는 **암호화되지 않은 민감자료**입니다. 원본 Burp XML과 마찬가지로 승인된 저장소에 접근권한·보관기간을 적용하세요. 암호화는 기관에서 사용하는 승인된 보관 수단으로 수행하세요. 마스킹 보고서도 비식별화가 보장되지 않으므로 공유 전에 검토해야 합니다. 자동 클라우드 업로드 기능은 없습니다.

## 바뀐 점

- 가져올 때 동일 URL·본문도 원거래별로 유지합니다. 파일 SHA-256, 원응답 SHA-256, 분석용 응답 SHA-256을 저장하고 마스킹 보고서에도 연결합니다. 해시는 출처의 진위나 변경 방지를 보증하지 않습니다.
- gzip·deflate, chunked 해제, 선언 문자셋(예: EUC-KR) 처리를 추가했습니다. 압축 전 Base64 원응답은 프로젝트에 보존합니다. 화면의 좌표는 압축을 해제한 분석용 텍스트의 문자 위치입니다.
- 응답 헤더, HTML 인라인 스크립트·속성, XML 속성, JavaScript 응답과 WebSquare XML을 텍스트로 보완 검사합니다. 불러온 코드를 실행하거나 외부 리소스를 로드하지 않습니다.
- 필드명 정규화, 국제·070 전화번호, 카드번호 형식을 보완했습니다. 계좌·여권·면허 전용 필드 후보를 추가했습니다. 후보는 실제 발급·유효성·소유자 확인 결과가 아닙니다. 일반 name은 상품명일 수도 있어 후보로 남깁니다.
- 후보는 기본 표시하고 정적 텍스트 제외는 기본 해제했습니다. 관리자 ID 추정은 기본 해제하고 호스트별 통계로 분리했습니다. 반복되는 ID가 관리자라는 뜻은 아닙니다.
- 손상 응답은 항목별로 실패 처리합니다. JSON 깊이·매치 수 등의 제한 도달은 일부 검사로 표시합니다. 최초 분석도 응답 사이에 UI 제어를 돌려주며 홈/클리어로 취소할 수 있습니다.
- 목록 마스킹은 상세에도 유지합니다. 원문 표시·복사는 확인 후 실행합니다. 주민번호 마스킹도 강화했습니다.
- 크롤러의 서로 다른 응답 누락, 공공 접미사 기준 범위 확대, EUC-KR 원문 훼손을 수정했습니다. 로컬 서버에 실행별 API 토큰·Host·Origin 검사 등을 추가했습니다.

## 압축·미지원 자료

최신 브라우저에서도 Brotli(`Content-Encoding: br`) 해독을 지원하지 않을 수 있습니다. 이 경우 해당 응답은 ‘미지원’으로 남고 완료로 계산하지 않습니다. 아래 로컬 도구로 변환한 XML을 불러오세요. 변환 도구는 대상 사이트에 접속하지 않습니다.

```bash
# Brotli가 필요할 때 한 번 설치 (gzip/deflate만 변환하면 불필요)
python -m pip install brotli
python normalize_burp.py input.xml normalized.xml
```

입력·요청은 변경하지 않고, 변환 XML의 `originalResponse`에 원응답을 보존합니다. 원응답 해시는 이 값으로 연결됩니다. 기존 출력 파일은 덮어쓰지 않습니다. 종료코드 0은 전 항목 변환, 2는 일부 실패, 1은 파일/XML 오류입니다. 일부 실패 응답은 `normalizationError`와 함께 남고 탐지기에서도 미완료로 표시합니다. 원본과 해제본을 함께 담아 파일이 커질 수 있으므로 Burp에서 나누어 내보내세요.

PDF·이미지·Office·압축파일 등의 본문 텍스트 추출/OCR은 제공하지 않습니다. 별도 승인된 도구로 검토해야 합니다. 가려진 번호의 복원, 암호화 값의 해독, 모든 언어·필드·인코딩의 개인정보 식별도 보장하지 않습니다. 알려진 필드 사전과 정규식은 기관별 정답셋으로 검증·보완해야 합니다.

## 처리 한도

| 항목 | 한도/처리 |
|---|---|
| 입력 파일 | 파일당 25MiB, 한 번 선택한 합계 50MiB |
| 프로젝트 | 입력 거래 20,000개, 누적 원문·원응답·요청 등 75Mi 문자 |
| 원응답/압축 해제 결과 | 8MiB |
| 분석용 응답 텍스트 | 4Mi 문자 |
| JSON 구조 분석 | 깊이 100 |
| 규칙별 한 값의 매치 | 50,000회, 초과 시 일부 검사 |
| 응답별 발생 결과 | 50,000회, 초과 시 일부 검사 |
| 원문 보완 필드 추출 | 응답당 10,000회, 초과 시 일부 검사 |

브라우저의 안전한 처리를 위한 상한이며 최대 한도에서의 성능을 보장하는 수치는 아닙니다. 단일 큰 응답의 DOM/정규식 처리는 잠시 UI를 점유할 수 있고 직접 입력한 복잡한 검색 정규식도 브라우저를 지연시킬 수 있습니다. 큰 자료는 분할하고 미분석 수를 대조하세요. ‘규칙 검사 완료’는 구현된 규칙이 실행됐다는 뜻이며 개인정보를 모두 찾았다는 뜻이 아닙니다. Burp에 수집되지 않은 API·계정·페이지는 이 도구가 검사할 수 없습니다.

## 선택: 로컬 웹 화면

Python 3.10 이상에서 다음을 실행합니다. Burp 분석 화면만 열 때는 크롤러 의존성이 필요 없습니다.

```bash
python webapp.py --open
```

Windows에서는 `run.bat`을 사용할 수 있습니다. 서버는 loopback에서만 실행하며 API 토큰은 시작할 때 새로 생성됩니다. 서버를 재시작했다면 화면도 새로고침하세요. 다른 PC에 서버를 공개하는 용도는 지원하지 않습니다.

## 선택: 크롤러

크롤러를 사용할 때만 설치합니다.

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python crawler.py https://agency.example.test/final-page --depth 1 --max-pages 30
```

Windows에서는 `install.bat`이 의존성과 Chromium을 설치합니다. 점검 승인된 초기 URL과 명시한 로그인 URL의 정확한 호스트만 허용합니다. `--allow-subdomains`는 그 호스트 **아래**의 서브도메인만 허용하며, 형제 기관의 `*.go.kr`를 같은 범위로 인정하지 않습니다. 외부 CDN·SSO를 임의로 허용하지 않으므로 관련 화면이 동작하지 않을 수 있습니다.

범위 이탈을 막기 위해 **내부·외부 HTTP 리다이렉트를 모두 차단**합니다. 최종 승인 URL을 직접 입력해야 합니다. 리다이렉트 기반 로그인/SSO에는 Burp로 수집한 XML을 사용하는 편이 적절합니다. 승인된 정확한 호스트 입력 자체의 적정성과 DNS·조직 소유권은 별도로 확인하세요.

원거래 캡처는 모두 저장하고, 기본으로 지정 비밀번호의 알려진 인코딩 형태와 Cookie/Authorization 등 헤더를 가립니다. 모든 개인정보·토큰이 제거되는 것은 아닙니다. 세션 파일과 `output/` 결과는 민감자료로 취급하세요. 로그인 성공은 사이트별로 별도 확인해야 합니다. LLM 자동 추출은 이 패키지에 포함하지 않습니다.

## 검증 자료

`tests/`에 합성 데이터 기반 회귀 검사가 있습니다. 실제 기관 대상 접속은 수행하지 않았습니다. 검증 범위와 결과는 `VALIDATION.md`를 참조하세요. 실제 Burp 버전/내보내기 설정과 기관별 데이터에서 탐지 재현율을 별도로 확인해야 합니다.
