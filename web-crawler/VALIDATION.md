# 수정본 검증 결과

검증 버전: 2.1.0. 실제 기관 시스템·실제 개인정보에 접근하지 않고 합성 응답으로 검증했습니다. Python 3.12, Node 24, 시스템 Chromium 154, Playwright를 사용했습니다. 기본 크롤러 의존성 전체 설치나 실제 외부 사이트 크롤링은 수행하지 않았습니다.

| 검사 | 결과 |
|---|---|
| 개인정보 규칙 회귀검사 | 32개 통과 |
| Burp 가져오기·브라우저 검사 | 24개 통과 |
| 크롤러·서버·변환 도구 Python 단위검사 | 46개 중 45개 통과, 1개 건너뜀 |
| UI 프로젝트 저장·복원·마스킹·다운로드 | 통과 |
| 실제 로컬 서버·iframe 연동·인증 검사 | 통과 |
| Python 및 HTML 내 JavaScript 구문검사 | 통과 |

대용량 추가 검증:

| 합성 파일 | 내용 | 브라우저 결과 |
|---|---|---|
| 80MiB | 실제 응답 1개 + XML 패딩 | 1개 전수 가져오기·해시 일치, 약 2.4초 |
| 100MiB | 74거래, 응답 본문 각 1MiB | 74개 분석 완료, 약 11.9초 |
| 500MiB | 실제 응답 1개 + XML 패딩 | 원본 524,288,000바이트 처리·해시 일치, 약 13.6초 |
| 500MiB | 374거래, 응답 본문 각 1MiB | 374개 분석 완료·원본 해시 일치, 약 63.5초 |
| 500MiB + 1바이트 | 상한 경계 | 파일당 한도 초과를 명시적으로 표시 |
| CDATA 청크 경계 | 응답 안의 `</item>` 및 청크 경계 CDATA 종료 | 정확한 항목 분리 |

위 시간은 이 검증 환경에서 관측한 값이며 다른 PC의 속도 보장이 아닙니다. 500MiB 실데이터형 시험의 응답 본문 총량은 392,167,424바이트이고 base64/XML 오버헤드를 포함한 입력은 524,288,000바이트였습니다. 원문 메모리 분리 여부는 응답 목록에 text/base64 원문 필드가 남지 않고 임시 저장소에서 정확히 복원되는 것으로 확인했습니다. 브라우저 전체 프로세스의 최대 메모리를 수치로 측정한 결과는 아닙니다.

스트리밍 파서·증분 해시 기능 검사 34개, IndexedDB 저장·복원·격리·삭제 검사 15개도 통과했습니다. 검색 범위 변경 후 재검색 및 임시 원문 유실 후 실패 표시를 확인했습니다. 대용량 프로젝트 JSONL 저장·복원과 검토 판정 보존, 상세 마스킹도 검사했습니다. 독립 시험에서는 100MiB의 74거래를 약 181MB JSONL로 저장하고 복원해 74개 응답/입력 해시와 원문·첫/마지막 검토 판정을 대조했습니다. 잘린 80MiB 파일은 정상 1건을 유지하되 파일 미완료·실패로 기록됐고, 500MiB 가져오기 중 홈으로 취소했을 때 빈 유휴 상태로 돌아오는 것도 확인했습니다. 큰 파일은 일반적인 메모리 전체 XML 파싱 경로를 사용하지 않습니다. 합성 fixture 생성기와 브라우저 검증 원자료는 tests/에 있습니다.

Brotli 선택 패키지가 설치되어 있지 않아 Python 실코덱 검사 1개를 건너뛰었습니다. 패키지 누락 처리와 압축 오류·제한 처리 등은 별도로 검사했습니다. 브라우저의 Brotli 미지원 상태가 명시적으로 집계되는 것도 확인했습니다.

관리형 Chromium 정책이 file:// 이동을 차단해 HTML 파일을 직접 여는 E2E 단계도 별도로 건너뛰었습니다. HTML 스크립트·파일 선택·다운로드는 브라우저 내에서 검사했고, 실제 로컬 HTTP 서버를 통한 화면과 iframe에서의 합성 응답 가져오기도 통과했습니다. 사용 환경의 파일 열기 정책이 같으면 `python webapp.py --open` 또는 `run.bat`으로 실행하세요.

가져오기 검사는 gzip·deflate·chunked·EUC-KR, 손상 Base64의 항목별 격리, 같은 본문의 200/500 거래 보존, HTML 스크립트·일반/엔티티 속성·XML 속성·응답 헤더, WebSquare XML, 깊은 JSON 제한, PDF 미지원 집계, 실제 FileReader·파일 SHA-256, 정규화 원응답 해시 연결을 포함합니다. UI 검사는 원문 프로젝트 round-trip과 검토 판정 보존, 상세 마스킹, 마스킹 보고서에 합성 이메일·쿼리 토큰·오류 원문이 들어가지 않는지 확인했습니다. 이 시험은 모든 개인정보 형식이나 모든 XSS·기밀성 문제가 없음을 증명하지 않습니다.

재실행(테스트용 도구 설치 필요):

```bash
cd web-crawler
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/test_detection.js
node tests/test_import_browser.js
node tests/test_ui.js
node tests/test_burp_stream.js
node tests/test_large_storage_browser.js
node tests/test_large_search_browser.js
# 큰 합성 파일을 준비한 경우: tests/test_large_import_browser.js 와 tests/test_large_workflow_browser.js 실행
python tests/smoke_server_browser.py
```

브라우저 테스트는 Node의 `playwright` 및 Python의 `playwright`가 필요합니다. JavaScript 테스트는 `CHROMIUM_PATH` 환경변수로 브라우저 경로를 바꿀 수 있으며 기본 경로는 `/usr/bin/chromium`입니다. 테스트는 일반 사용을 위한 필수 설치 항목이 아닙니다. 일부 테스트는 소스 함수를 추출하거나 브라우저 메모리 안에서만 테스트용 접근자를 추가합니다.

실제 Burp 버전과 내보내기 설정, 사이트별 권한·업무 응답, 기관별 필드와 번호 형식의 재현율, 대용량 운영 성능은 배포 환경에서 추가 검증해야 합니다. ‘완료’ 건수는 규칙 실행의 회계이며 개인정보 부재 판정이 아닙니다.
